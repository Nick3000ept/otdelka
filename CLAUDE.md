## Архитектура коротко

- **Auth**: общий пароль (не индивидуальные токены) → localStorage (`otdelka_token`) → бэк сверяет `t=` с Script Properties `PASSWORD` на каждый запрос.
- **doGet?action=load** — единственный эндпоинт с данными: `{ works, expenses, materials }`,
  ~600 КБ. Из `works` бэкенд отсекает строки с пустым
  `Название работы из АР`: в листе ~818 строк-призраков, где заполнена только ячейка
  «Плановый процент переделки» (формула растянута по столбцу). После отсева работ **321**,
  ответ похудел с 960 до 548 КБ. Понадобятся эти строки — снять фильтр в `load`.
  Там же отсекается **место «1 этаж»** (`CONFIG.EXCLUDE_PLACES`, решение пользователя
  2026-08-03) — это 190 работ из 321. Итого витрина видит **131 работу**, 20 групп,
  4 места (Квартира, Лестница, МОП, Технические помещения), 58 работ с признаком
  ген. объёма; ответ 487 КБ.
- **Скрытые колонки работ** (список `HIDDEN_COLS` в `index.html`, решение пользователя
  2026-08-03): Название работы СС, ИД факт, три «Признак для бюджета…», Признак Уровень 1
  ДГП для увязки, Материалы. Данные приходят с сервера, но не показываются и не участвуют
  в поиске.
- **Колонка «Ген. объем»** (2026-08-03) — галочка ✓ там, где заполнен
  `Признак для бюджета дополнительный объем` (`hasVolume()`), сразу за названием работы.
  ⚠️ В этой колонке Sheets лежит **не «да/нет», а название группы** (Стяжка, Окраска…):
  заполнено у 73 работ из 321, у 53 из них значение совпадает с «Группой работ».
  Признак означает «работу учитывать при расчёте объёма».
- **Группировка и фильтры** (2026-08-03): работы сгруппированы по `Группа работ`,
  **на старте все группы свёрнуты**, кнопка «Развернуть все / Свернуть все» рядом с фильтрами.
  Группы сворачиваются кликом по заголовку (`state.collapsed`), порядок групп — как в листе
  (по первому появлению, не по алфавиту). Сама колонка «Группа работ» скрыта — значение
  в заголовке группы. Сверху три выпадающих фильтра (Группа работ · Место · Поверхность,
  значения собираются из данных, сортировка `localeCompare('ru')`) + кнопка «Сбросить»;
  фильтры комбинируются с поиском. В счётчике — «N из M · групп: K».
  Колонка `Название работы из АР` переносится по словам (класс `wname`), остальные — в одну строку.
- **Оформление таблицы работ** (2026-08-03): `Место`, `Поверхность`, `Локация` не отдельные
  колонки, а одна ячейка с тегами-пилюлями (`TAG_COLS` / `cellHtml`) **последней колонкой**;
  фильтры и поиск при этом работают по исходным колонкам. Слева у работы только треугольник —
  счётчик материалов оттуда убран (в узкой ячейке он обрезался в «…»).
  Денежные колонки (`MONEY_HINT`: расценка, цена, стоимость, руб) — всегда 2 знака после
  запятой, остальные числа — до 4. Все числовые колонки одной ширины: 150px в таблице работ,
  120px в списке материалов.
  Короткие заголовки — словарь `RENAME` в `index.html` (ключ = имя в Sheets):
  «Базовая расценка работа в расчет, руб» → **Баз. расценка раб.**,
  «Стоимость материалов базовая, за ед» → **Баз. расценка мат.**,
  «Плановый процент переделки» → **% переделки**. Переименование только на витрине;
  числовое/денежное форматирование определяется по исходному имени, не по короткому.
- **Колонки раскрытого списка материалов** — жёстко заданы в `DETAIL_COLS` (`index.html`),
  порядок по просьбе пользователя 2026-08-03:
  Материалы · **Ед. изм. материала** · Слои · **Расход** · **Расход итого** · Расценка ·
  Стоимость материала в ед работы, внизу строка **«Итого материалов на ед. работы»** —
  сумма по колонке `Стоимость материала в ед работы` (`SUM_COL`).
  «Ед. изм. материала» берётся из справочника `Материалы` (колонка `Ед. изм`) по названию
  материала: совпало 531 из 547 строк, у 16 в справочнике пусто — ячейка пустая.
  Единица измерения работы в списке не дублируется — она есть в строке работы выше.
  Не показываем: Место, Тип работ, Объем работ, Объем материала, Название работы из АР.
  «Расход» — вычисляемая колонка: берём «Ручной расход», если он заполнен, иначе
  «Расход автомат» (в данных ручной заполнен всего в 8 строках из 1010, автомат — в 547;
  у 463 строк пусты оба, там колонка пустая). «Расход итого» — это лист-колонка
  «Расход в рачет» (опечатка в названии — на стороне Sheets, переименована только на витрине).
- **Раскрытие материалов**: индекс `Map(название работы → строки «Расходов»)` строится один
  раз после загрузки; клик по строке вставляет вложенную таблицу (все колонки «Расходов»,
  кроме названия работы). У 266 работ из 321 материалы есть (в среднем 2,1, максимум 11),
  у 55 — нет, для них подпись «Материалы … не найдены». Клики ловятся делегированием
  на `tbody`, `onclick` в разметку не вшивается.
- **doGet?action=ping** — диагностика (тоже требует пароль).
- **doGet?action=meta** — оглавление таблицы: имена всех вкладок, число строк/колонок,
  заголовки колонок. **Без единой строки данных** — ответ ~3 КБ, безопасно смотреть из чата
  (см. раздел про лимит выше). Фронтом не используется, нужен для диагностики и сессий Claude.
- Только чтение — `doPost` не реализован, записи в Sheets из витрины нет.
- Рендер таблиц — чанками по 300 строк через `requestAnimationFrame`, чтобы не подвешивать вкладку на ~1000+ строк.
- Поиск — по всем колонкам сразу, debounce 150мс, без запроса к серверу (все данные уже на клиенте).

## ⚠️ Данные в чат не тянуть (инцидент 2026-08-02)

Ответ `?action=load` — **~980 КБ** (Работы 1139×17, Материалы 273×6, Расходы 1010×13),
это ~300–500 тыс. токенов. Один вывод этого ответа в переписку съедает весь дневной лимит
Claude за один запрос. Боевая «Отделка СБ3 база» (12 МБ) — ещё хуже.

Правила для будущих сессий:
- **Никогда** не печатать ответ `load` (и любой дамп листов) в чат целиком — ни через
  `Invoke-WebRequest`, ни через `WebFetch`, ни через MCP Google Drive.
- Нужно проверить, что бэк жив → запрашивать `?action=ping` (ответ ~60 байт).
- Нужно узнать структуру/объём → выводить только агрегаты: `.Length`, `.Count`,
  список названий колонок. Пример безопасной команды:
  ```powershell
  $r = Invoke-WebRequest -Uri "<URL>?action=load&t=<пароль>" -UseBasicParsing
  "bytes: " + $r.Content.Length
  ($r.Content | ConvertFrom-Json).works.Count
  ```
- Нужно посмотреть примеры строк → максимум 3–5 строк, не весь лист.
- Если данные нужно анализировать всерьёз — сохранять в файл в scratchpad и работать
  запросами по файлу (фильтр/подсчёт), а не читать файл целиком.

## Известные нюансы

- **Новый GAS-проект после `clasp deploy` не сразу доступен анонимно** — даже с `"access": "ANYONE_ANONYMOUS"` в манифесте, реальный доступ пришлось один раз вручную подтвердить в редакторе (Развертывание → Управление развертываниями → карандаш → проверить «У кого есть доступ» → Развернуть). Для существующих проектов (передеплой через `update-deployment`) этот шаг не нужен.
- **`clasp run` не работает** — «Google Apps Script API» не включён для аккаунта `kuzkin@acons.group` (Script function not found / API executable). Функции типа `setup()` в Script Properties приходится запускать вручную через редактор (▷ «Выполнить» → выбрать функцию → авторизовать).
- Если понадобится сменить пароль — поменять в `script.gs` функции `setup()` и один раз выполнить её заново в редакторе, либо вручную через «Настройки проекта → Свойства скрипта» в редакторе GAS.
- GitHub Pages и включение доступа GAS webapp настраивались вручную в вебе (не через API — не было ни `gh` CLI, ни валидного GitHub-токена на момент разработки).
